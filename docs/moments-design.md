# 动态：直接可用，按需自定义

目标是有生活感、有陪伴感，保留已有动态玩法，减少使用前的配置。

## 设置位置

动态页管理全局默认；聊天设置管理单个角色；人脉配置管理单个 NPC。每一项独立继承或覆盖，不再提供对象两两组合、逐帖规则、批量配置、时间窗口、额度和重试配置。

角色主动活动只跟随正常聊天与原本已开启的后台消息，不再提供独立发帖检查间隔、活跃度预设或自动发布冷却。允许发布时，由 API 自己决定发或不发；关闭发动态或 Story 权限后，不注入对应能力并拦截执行。

聊天设置的“后台自主发布动态”控制后台动态和 Story，默认允许，仍需开启原后台自动消息任务及对应发布权限。关闭后，后台提示词不注入发布指令或允许发布的能力说明；普通聊天和后台聊天消息不受此开关影响。NPC 的主动活动跟随所属角色的正常聊天或后台消息，每个 NPC 使用自己的 API 与独立上下文；后台发布也遵守所属角色的开关。

角色与 NPC 的评论回复等待时间、互相接话轮数及各项参与方式继续独立配置，已有有效设置保留。

互相接话轮数独立设置，默认 0（禁止角色和 NPC 互相接话）。首次评论和对用户评论的一次回复不消耗互相接话轮数；正整数允许有限的 AI 接话，每人每轮最多一次，所有写入入口统一检查。每个对象每条动态最多留一次初始评论，重复浏览不能重开讨论；用户新评论可继续交流。允许的活动可以选择暂不行动。网页关闭时不能保证定时执行，重新打开会恢复尚未完成的观看任务。

发动态、Story、观看、自主浏览、点赞、发表评论、回复评论、人脉参与是独立选择。单个对象可以不发动态、不回评论，同时继续观看或点赞。

“聊天关联动态”默认开启，可在全局动态设置中关闭；角色聊天设置可选择跟随全局、开启或关闭。关闭后，聊天不再自动注入动态能力、已看内容、评论、提醒、操作经历和动态主页信息，动态仍会参考聊天与共同记忆。动态参与方式、发布或评论触发的互动和旁白显示不受此设置影响；已有聊天和记忆不会被清理。

## 发布、观看和提醒

发布成功后，立即为可见且允许观看的角色和 NPC 安排观看。无需选择提醒对象，也不需要另外打开调用入口。提醒意味着立即提醒并安排观看，角色知道你提醒了他。同一次发布对同一对象只安排一次观看。编辑时新增的提醒会立即安排一次观看，包括已经看过的对象。评论节奏不延迟第一次观看。

保留正文、图片、视频、语音、表情包、Story、可见范围、分组、提醒、身份选择、点赞评论、评论编辑与删除、动态管理、人脉和好友申请。

## 人设与关系

观看、评论和接话关联角色设定、动态对应的用户身份、绑定的补充或覆盖设定、双方已有关系与聊天、启用的记忆及世界书、可见评论与媒体信息。身份占位符使用本次身份解析。切换展示身份不重写旧帖作者。

每个参与者独立请求，使用自己的 API 与上下文。NPC 只获得自己的设定、亲历记录和明确绑定的世界书，不继承所属角色的私聊和共同记忆。

## 观看情况

展示等待、正在观看、已观看并互动、选择不回应、互动被设置拦截、取消、中断和失败。拦截及报错有明确原因；原始返回折叠到详情。动态修改、删除或权限变化后，迟到返回不能写入。保存失败不能显示为成功。

## 已有数据

保留动态和身份记录，迁移已有有效节奏与对象明确的行为选择。旧调用开关、逐帖规则、两人组合、时间窗口和额度不再影响新流程。未单独设置的项目随全局变化，已有覆盖不会被全局预设重写。

首次加载新接话规则或导入旧备份时，旧的全局和对象接话轮数关闭，已有时间、参与方式、评论、通知和身份记录保留。旧讨论不再自动续接；旧 AI 接话任务取消，迟到结果不能写入。尚未回复的用户评论仍可收到一次回复。迁移标记持久保存，不会覆盖用户之后主动设定的有限轮数。

取消独立调度时只停止旧的定时自主活动任务，保留等待中的观看、用户评论回复、动态历史及原参与方式。关闭发布权限或后台发布开关后，正在生成的迟到结果不得发布。
